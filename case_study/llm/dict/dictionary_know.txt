────────────────────────────────────────────────────────────────────────────────
0. What We Are Doing (One-sentence Summary)
────────────────────────────────────────────────────────────────────────────────

  Pre-capture ciphertext for known token sequences such as "Chest pain",
  store them in a dictionary, and later compare against ciphertext from
  guest memory during inference to identify "which phrase was present at this location".
  This document explains the pre-capture process (= Dictionary Build).

  Core Premise (SEV-SNP AES-XEX):
    Same plaintext + same physical address (GPA) = always identical ciphertext.

  Thus: If token IDs for "Chest pain" are placed at a known GPA and dumped once,
  when a real indication later lands at that GPA (specifically that offset),
  comparing ciphertext alone determines if it was "Chest pain".

────────────────────────────────────────────────────────────────────────────────
1. Why is it Complex? — Placing Target Tokens at Target GPAs
────────────────────────────────────────────────────────────────────────────────

  We send ICMP packets from the host through the guest kernel with payloads
  containing our chosen token IDs. However, where those packets land in guest
  memory (which physical page, which offset) cannot be directly assigned from host
  — it depends on internal kernel buffer allocation states.

  The challenge solved by dictionary construction:
    "Given control over content but not location, ensure an entire page is
     completely populated with our repeating token pattern and accurately determine
     its exact physical address."

────────────────────────────────────────────────────────────────────────────────
2. Guaranteeing a "Full Page" via Large Payloads
────────────────────────────────────────────────────────────────────────────────

  Idea: Repeat the token sequence (e.g. "Short of breath" = 3 tokens = 24 bytes)
  repeatedly across a large payload (12,288 bytes = 3x 4KB pages, ICMP_PAYLOAD_MIN)
  inside a single ICMP packet:

    [token][token][token][token][token]... (24-byte pattern repeating to 12288B)

  Regardless of where this data lands or how it is offset from page boundaries,
  because the payload is sufficiently long (>= 2x 4096 - 1 = 8191 bytes guarantees
  at least one full page mathematically), at least one intermediate 4KB page is
  guaranteed to be completely filled with our repeating pattern from start to finish.

  Analogy:
    Imagine an infinite tape repeating "ABCABCABC..." packed across several boxes.
    Boxes at the edges may cut off partially (e.g. starting with "BCA"), but
    intermediate boxes are 100% filled with the "ABC" pattern without contaminants.

  Locating and capturing this intermediate 100% clean page is Step 1.

────────────────────────────────────────────────────────────────────────────────
3. Packet Fragmentation
────────────────────────────────────────────────────────────────────────────────

  When sending a 12,288-byte packet, the guest kernel splits it across multiple
  physically disjoint fragments (frag[0], frag[1], frag[2]...) rather than
  one contiguous buffer.

  The guest kernel module logs in dmesg:
    frag[0]: compound_GPA=0x142700000  off=46      size=8976
    frag[1]: compound_GPA=0x142700000  off=9262     size=3320

  We collect all candidate 4096B clean pages across all fragments.
  Note that the front of frag[0] contains ICMP header (8 bytes) + byte_shift padding,
  so true token data starts at (frag start + 8 + byte_shift). Subsequent fragments
  have no ICMP headers.

────────────────────────────────────────────────────────────────────────────────
4. 8-Byte Alignment (byte_shift)
────────────────────────────────────────────────────────────────────────────────

  Indication tokens in memory are always 8-byte aligned (int64 tokens, 8-aligned arrays).
  If actual_landing (where clean token cycles start on the page) is not divisible by 8
  (e.g., 6, 14, 22), the dictionary entries will never match real 8-aligned queries.

  Solution: Insert `byte_shift` bytes of 0x00 padding at the front of the payload.
  Adjusting padding shifts where token data starts in memory:
    If landing % 8 != 0 -> increase byte_shift by (8 - landing%8) and retransmit.

────────────────────────────────────────────────────────────────────────────────
5. Why Rotations are Necessary — ABC / BCA / CAB
────────────────────────────────────────────────────────────────────────────────

  For an N-token label (e.g., "Short of breath" = [A, B, C], 24 bytes), tokens
  can start at any offset mod 24 in real memory (residue 0, 8, or 16).
  A single page repeating "ABC" only covers offsets starting with "A".
  If real indication starts at residue 8 (= "B" first), an "A"-aligned dictionary misses.

  Therefore, we transmit all cyclic permutations:
    rotation 0: A B C A B C ... (original sequence)
    rotation 1: B C A B C A ... (1-step rotation)
    rotation 2: C A B C A B ...

  Building all N permutations guarantees covering residues 0, 8, ..., (N-1)*8.
  2-token labels also follow this rule (rotation 0: [A,B], rotation 1: [B,A]).

────────────────────────────────────────────────────────────────────────────────
6. Handling Collisions
────────────────────────────────────────────────────────────────────────────────

  Which residue a rotation covers depends on `actual_landing`:
    reg_start = (actual_landing - rotation_idx * 8) % L

  If two rotations land on the same residue due to kernel buffer variations,
  a collision occurs, leaving another residue uncovered.

  Resolution:
    Track `covered_residues` for each label.
    1. Priority 1: If an aligned candidate covers an unvisited residue, adopt immediately.
    2. Priority 2: If all aligned candidates collide with existing residues,
       increment `byte_shift += 8` and retransmit (up to 40 retries).

────────────────────────────────────────────────────────────────────────────────
7. Summary of Entire Build Workflow
────────────────────────────────────────────────────────────────────────────────

  For each label (e.g., "Short of breath", 3 tokens, L=24):
    covered_residues = set()
    for rotation in [ABC, BCA, CAB]:
        if covered_residues == achievable_residues:
            break
        while not succeeded and tries < 40:
            1. Transmit ICMP packet with byte_shift padding + repeated pattern
            2. Parse frag[0], frag[1]... from guest dmesg
            3. Gather all clean 4096B page candidates
            4. Filter for actual_landing % 8 == 0 (aligned)
            5. If candidate covers a new residue -> adopt, break
            6. If all candidates collide -> byte_shift += 8, retry
        Dump page with read_gpa and register entries in dict_cache.json for
        reg_start, reg_start+L, reg_start+2L...

  Repeated for all labels across all cyclic rotations.
  Outputs: `dict_cache.json` and `dict_pages/*.out`.

────────────────────────────────────────────────────────────────────────────────
8. Utilizing the Dictionary During Inference (run_all Integration)
────────────────────────────────────────────────────────────────────────────────

  During inference tracking:
    1. Obtain base_gpa and N from guest
    2. Compute exact indication start: tok_start = HEADER_CONST + N
    3. Query `dict_cache.json` for offset (tok_start * 8) % 4096
    4. Swap-read indication page and compare ciphertext against dictionary dumps via AES-XEX blocks
    5. Exact match identifies the clinical indication.
