────────────────────────────────────────────────────────────────────────────────
0. Overall Objective
────────────────────────────────────────────────────────────────────────────────

When running LLM (Medical VLM) inference inside an AMD SEV-SNP encrypted guest VM,
infer indication tokens from the host without decrypting guest memory
using a side-channel attack PoC (Dictionary-based ciphertext comparison).

Core Principle:
  In AES-XEX encryption, identical plaintext + identical GPA (Guest Physical Address) =
  always identical ciphertext. Therefore, comparing ciphertext captured from a known
  token at a known GPA against ciphertext at the GPA where the indication token resides
  enables token identification.

────────────────────────────────────────────────────────────────────────────────
3. HEADER_CONST and indication_gpa Computation
────────────────────────────────────────────────────────────────────────────────

  During guest LLM inference, when input_ids array is placed in memory:
    - Prompt header tokens appear first (HEADER_CONST tokens)
    - Image padding tokens follow (N_image_pad = N tokens)
    - Clinical indication tokens appear immediately following

  Therefore:
    tok_start      = HEADER_CONST + N
    indication_gpa = base_gpa + tok_start * 8

  Current value: HEADER_CONST = 43 (hardcoded in codebase, see §17 and §19)
  indication_page_gpa = indication_gpa & ~0xFFF   (4KB page-aligned)
  token_offset        = indication_gpa & 0xFFF     (in-page byte offset)

────────────────────────────────────────────────────────────────────────────────
4. Phase 0: Dictionary Build (--build)
────────────────────────────────────────────────────────────────────────────────

Goal: Pre-capture ciphertext for all token_idx (0~3) x all possible page offsets
      and persist in dict_cache.json.

4-1. Always Fresh Build
  Running --build deletes existing dict_cache.json and dict_pages/*.out.
  No intermediate resumption — fresh build from scratch.

4-2. Phase-Based Optimization
  Each token_idx has payload length of token_len(L) bytes.
  L = len(token_ids) * 8    (token_idx=0,2: L=16,  token_idx=1,3: L=32)
  n_phases = L // 8          (token_idx=0,2: 2 phases,  token_idx=1,3: 4 phases)

  Phase p captures when the first token byte lands at target_landing = p*8.
  Since payload repeats every L bytes, a single dump covers:
    p*8, p*8+L, p*8+2L, ...

  Total phases: 143 phases (based on 35 TOKEN_LABELS, see §20)
  Total transmissions: 4 probes + 1 aligned for first phase of each token_idx, 1 carry-forward for subsequent phases
    -> 35x5 + 108x1 = 283 transmissions (assuming no landing retries)

4-3. Processing Flow per Phase
  a. Ring state carry-forward (except first phase):
       Reuse actual_frag_p1 and delta from previous phase if available.
       expected_frag = (frag_p1_last - delta) % 4096 (requires only 1 aligned send)

  b. When probe missing: Small probe x 2 (prefix=0):
       acquire_token_gpa(token_idx, prefix=0) x 2
       -> obtain frag_p1_a, frag_p1_b
       delta_small = (frag_p1_a - frag_p1_b) % 4096
       expected_frag_rough = (frag_p1_b - delta_small) % 4096

  c. Large probe x 2 (prefix = target_landing + expected_frag_rough):
       acquire_token_gpa(token_idx, prefix=_large_pfx) x 2
       -> obtain frag_p1_c, frag_p1_d (matching aligned send packet size)
       delta_large = (frag_p1_c - frag_p1_d) % 4096
       expected_frag = (frag_p1_d - delta_large) % 4096
       prefix = target_landing + expected_frag

  d. Aligned send:
       acquire_token_gpa(token_idx, prefix=prefix)
       -> obtain dict_gpa, actual_frag_p1
       actual_landing = (prefix - actual_frag_p1) % 4096
       -> must match target_landing exactly

  e. Landing retries (max _MAX_LANDING_TRIES=20):
       If actual_landing != target_landing:
         error = (actual_landing - target_landing) % 4096
         delta_corrected = (delta - error) % 4096
       Every 5 tries: re-probe (2 small + 2 large = 4 packets)
       Wrong-landing entries are preserved in cache as valid ciphertexts for their landed offsets.

  f. 4KB Page Dump:
       Save ciphertext of dict_gpa via read_gpa.py -> dict_pages/t{token_idx}_p{phase}.out

  g. Dictionary Registration:
       For off_key at actual_landing + k*L (k=0,1,2,...):
       save cache[off_key][str(token_idx)] = {gpa, cp_file, landing_ok}

  h. Save dict_cache.json upon completing each token_idx.

4-4. acquire_token_gpa Internal Mechanism
  - Clear guest dmesg (ssh "sudo dmesg -C")
  - Send ICMP packet from host (send_tokens.py)
  - Parse "sub-page[N] GPA=0x..." pattern from guest dmesg -> obtain GPA
  - Parse "frag[0] ... off=NNN" pattern -> compute frag_p1
  - Raise RuntimeError after 5 failures -> caller skips phase

4-5. Buffer Drain
  Force flush guest ICMP receive buffer every DRAIN_EVERY(=16) phases
  to prevent buffer accumulation from distorting subsequent measurements.

────────────────────────────────────────────────────────────────────────────────
5. do_swap_read: Atomic Swap-Back Read
────────────────────────────────────────────────────────────────────────────────

Non-destructive page reading used in both compare and calibrate:

  1. Invoke swap_pages_tool --swap-back:
       forward swap(dict_gfn <-> src_gfn)
       -> src data placed in dict_gfn physical frame (AES-XEX: dict_gfn tweak applied)
       -> copy ciphertext to kernel buffer
       -> backward swap (restore original state)
     -> All executed as a single atomic operation before svm_vcpu_run()
     -> Guest never observes swapped state (no SEV_TERM)

  2. KVM_READ_PAGE_DUMP ioctl on /dev/kvm:
       Copy 4096 bytes from kernel buffer to host userspace

  3. Format in xp /512gx format and save to .out file

  KVM_READ_PAGE_DUMP = _IOR(0xAE, 0x2b, 4096) = 0x80100AE2b

────────────────────────────────────────────────────────────────────────────────
6. Phase 1a: HEADER_CONST Auto-Calibration (--calibrate)
────────────────────────────────────────────────────────────────────────────────

  Used when exact value of HEADER_CONST is unknown or needs verification.

  Workflow:
    1. Acquire base_gpa, N from guest in --gpa-only mode (_acquire_gpa_raw)
    2. Sweep h from CAL_H_MIN(30) to CAL_H_MAX(60) in steps of 1:
         tok_start    = h + N
         token_offset = (base_gpa + tok_start*8) & 0xFFF
         src_gpa      = (base_gpa + tok_start*8) & ~0xFFF

         - Skip if token_offset not in dict
         - Execute do_swap_read for each token_idx in dict:
             save cal_h{h}_t{token_idx}.out
         - Compare cp (dict dump) vs post (read dump) via verify.py
         - Return h upon "Result: MATCH" (terminate sweep)

    3. If no matching h found, return None -> expand range or rebuild dictionary.

  AES Alignment and Retry Logic:
    - Cause of calibrate failure: When token_offset % 16 == 8:
      2-token (16B) labels have 0 clean AES blocks -> verify always fails.
      4-token (32B) labels contain at least 1 clean 16B block -> verifiable.

    - CAL_MAX_RETRIES = 3
      Each attempt acquires fresh base_gpa from guest.
      Probability of acquiring favorable alignment within 3 tries approx 87%.

7. Phase 1b: Single Index Inference (--index N)
────────────────────────────────────────────────────────────────────────────────

  Calls _run_single(args, cache, index):

  Step 1: Acquire indication_gpa
    - Call acquire_indication_gpa(index)
    - _acquire_gpa_raw: Execute guest script over SSH
        Parse "input_ids base GPA: 0x..." and "N_image_pad: N" from terminal stdout
        Max 3 retries, timeout 150s
    - indication_gpa = base_gpa + (HEADER_CONST + N) * 8

  Step 2: Dictionary Comparison
    - indication_page_gpa = indication_gpa & ~0xFFF
    - token_offset = indication_gpa & 0xFFF
    - compare_with_dict(cache, indication_page_gpa, token_offset, swap_tool)

  Step 3: Save Results
    - save_result(index, token_idx_found, verdict, indication_gpa, save_csv)
    - Append to results_v2.csv when --save-csv is specified

────────────────────────────────────────────────────────────────────────────────
9. compare_with_dict Internal Operation
────────────────────────────────────────────────────────────────────────────────

  token_offset -> off_key(hex) -> query cache[off_key]

  For each token_idx (0~3):
    1. Query dict_gpa, cp_file (dict dump path) from cache
    2. do_swap_read(swap_tool, dict_gpa, indication_page_gpa, post_path)
         -> read indication page using dict_gpa AES-XEX tweak
         -> save to post_path
    3. Compare via verify.py:
         --cp:           Dictionary ciphertext
         --post:         Captured indication page ciphertext
         --token-offset: In-page token offset
         --token-ids:    Token ID sequence
    4. "Result: MATCH" -> return (token_idx, "MATCH") immediately
    5. All MISMATCH -> return (None, "MISMATCH")

────────────────────────────────────────────────────────────────────────────────
10. verify.py Comparison Logic
────────────────────────────────────────────────────────────────────────────────

  parse_dump(path): Convert xp /512gx text -> raw bytes

  clean_aes_blocks(token_offset, token_len):
    Return list of 16-byte AES block offsets fully contained within
    token byte range [token_offset, token_offset+token_len).
    Exclude partial boundary blocks.

  cmd_verify:
    Compare cp vs post across each block in clean_aes_blocks list.
    All blocks match -> "Result: MATCH"
    Any mismatch -> "Result: MISMATCH"

16. HEADER_CONST / N Concept and --blind Mode
────────────────────────────────────────────────────────────────────────────────

16-1. Purpose of Both Parameters
  Memory layout of input_ids in guest CPU memory:
    [ Header tokens x HEADER_CONST ]
    [ <|image_pad|> tokens x N     ]
    [ Indication tokens            ]  <- Target

  Host computes indication GPA via:
    indication_gpa = base_gpa + (HEADER_CONST + N) * 8

  - base_gpa: GPA of input_ids[0].
  - HEADER_CONST: Constant across all samples for a fixed prompt template (43).
  - N: Number of <|image_pad|> tokens inserted per image (range: 80~1178).

16-2. Determination of N
  Qwen2-VL adjusts input images via smart_resize() to multiples of 28,
  partitions them into 14x14 patches, and compresses groups of 4 into 1 token:
    resized_h, resized_w = smart_resize(orig_H, orig_W, factor=28)
    N = (resized_h // 14) * (resized_w // 14) // 4

16-3. Blind Mode Mechanism
  Sweep tok_start = HEADER_CONST + N in [110, 1240]:
    1. Parse base_gpa only from guest
    2. Sequentially sweep tok_start in [110, 1240]:
         ind_gpa = base_gpa + tok_start * 8
         token_offset = ind_gpa & 0xFFF
         swap-back read + verify
         "Result: MATCH" -> terminate and return match
    3. Confirms tok_start, indication_gpa, and token_idx simultaneously.

────────────────────────────────────────────────────────────────────────────────
17. Two-Phase Blind Sweep (Binary Search)
────────────────────────────────────────────────────────────────────────────────

  Array Structure of input_ids:
    [0..FIRST_PAD_POS-1]       : Fixed header tokens (15)
    [FIRST_PAD_POS..+N-1]      : <|image_pad|> x N
    [FIRST_PAD_POS+N..+POST-1] : POST_SCAN tokens (20~60)
    [FIRST_PAD_POS+N+POST..]   : Indication tokens <- Attack Target

  Phase 1 — Binary search for N estimation (_binary_search_ipad_end):
    Target: Last tok_start where image_pad sentinel (token_idx=34) evaluates True.
    Search range: lo = 15, hi = 1215.
    Swap count: ceil(log2(1200)) approx 11 swaps (~100x improvement over linear).
    N_est = last_true - FIRST_PAD_POS + 4

  Phase 2 — Indication matching:
    tok_start in [FIRST_PAD_POS + N_est + POST_SCAN_MIN - 1,
                 FIRST_PAD_POS + N_est + POST_SCAN_MAX + 1]
    Compare against TOKEN_LABELS 0~33 (excluding sentinel).
    Takes <= 63 candidate steps.
