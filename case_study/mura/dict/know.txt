출처: mura_dict_build.py --build 실행 결과 직접 관찰

[1] 빌드 파이프라인 개요

    목적: 64개 REF_U8 값 각각에 대해 ref_XXX.out 파일 생성 (SEV-SNP XOR slice dict)
    도구: mura_dict_build.py (이 디렉토리)

    1회 빌드 = FIXED_GPA 획득 (zero payload) + 64개 ref GPA 획득 + swap_read

    GPA 획득 절차 (acquire_gpa):
    1. probe1: zero ICMP 전송 → dmesg에서 frag[0] off=N 파싱 → frag_p1_a 계산
    2. probe2: 동일 반복                                       → frag_p1_b 계산
    3. delta = (frag_p1_a - frag_p1_b) % 4096
       expected_frag = (frag_p1_b - delta) % 4096
    4. aligned send: prefix=expected_frag 바이트 zero + ref payload
       → sub-page[1] byte 0 = REF_CHUNK_X 첫 바이트

    frag_p1 계산식:
        frag_off = frag[0]의 off 필드 값
        frag_p1  = 4096 − (frag_off % 4096) − 8   (8 = ICMP echo 헤더)

    sub-page[1] GPA 계산식:
        compound_gpa = frag[0] 라인의 compound_GPA 필드
        frag_off     = 동일 라인의 off 필드
        start_page   = frag_off // 4096
        sub_page1_gpa = compound_gpa + (start_page + 1) × 4096

    PAYLOAD_SIZE = 8193 (고정):
        → probe/aligned 모두 동일 크기 사용
        → sub-page[1] 항상 payload로 완전히 덮임 (GPA 안정)

[2] 발생한 문제 — 증상 진행

    증상 1: frag_p1 parse failed (초기, probe sleep 너무 짧을 때)
        원인: dmesg 읽기 전 sleep 0.5s — dmesg에 아직 출력 없음
        해결: 1s + 최대 3×2s retry (총 최대 7s 대기)

    증상 2: --build 재실행 시 기존 항목 skip (item 45부터 재개)
        원인: 코드에 DICT_CACHE 로드 + 기존 항목 skip 로직이 있었음
        해결: build() 함수에서 cache 로드 및 skip 로직 완전 제거
              → --build 실행마다 항상 처음부터 새로 빌드

    증상 3: ** 14 printk messages dropped ** (dmesg에 출력됨)
        원인: /proc/sys/kernel/printk_ratelimit 기본값이 양수
              → 전역 printk_ratelimit() 함수가 메시지 드랍
        해결: SSH 초기화 시 printk_ratelimit=0 설정
              echo 0 | sudo tee /proc/sys/kernel/printk_ratelimit

    증상 4: [!] No GPA (item 63/64)
        원인: 'sub-page[N] GPA=...' 라인이 dmesg에 없음
              → 해당 라인은 printk_ratelimited() 매크로 사용
              → sysctl printk_ratelimit=0 과 무관하게 드랍됨
        해결: sub-page GPA를 frag[0] 라인에서 직접 계산
              (_parse_sub_page1_gpa 함수 신규 작성)

    증상 5: frag_p1 parse failed (item 64/64) ← 최종 장애
        dmesg에 3줄만 출력:
            guest_large_icmp_monitor: handler fired!
            icmp type=0 ...
            payload_len=... nonlinear=1
        'frag[0]' 라인 자체가 없음 (4번째 줄부터 전부 소실)

[3] 근본 원인 — printk_ratelimit vs printk_ratelimited 구분

    구분           printk_ratelimit()          printk_ratelimited() 매크로
    ──────────────────────────────────────────────────────────────────────
    제어 방식      전역 단일 카운터            호출 위치마다 DEFINE_RATELIMIT_STATE
    sysctl 제어    /proc/sys/kernel/            없음 (sysctl로 리셋 불가)
                   printk_ratelimit=0
                   으로 끌 수 있음
    버스트 한도    sysctl printk_burst          DEFAULT_RATELIMIT_BURST = 10
    창 크기        sysctl printk_ratelimit      DEFAULT_RATELIMIT_INTERVAL = 5s
    리셋 방법      sysctl 값 변경               해당 모듈 rmmod + insmod
    드랍 알림      "** N printk messages        없음 (조용히 드랍됨)
                    dropped **" 출력

    게스트 LARGE_ICMP 커널 모듈:
        handler fired!    → printk()          (제한 없음)
        icmp type=...     → printk()          (제한 없음)
        payload_len=...   → printk()          (제한 없음)
        frag[0] ...       → printk_ratelimited()  ← 4번째 줄부터 제한됨
        sub-page[N] GPA=  → printk_ratelimited()

    5초 창에서 burst=10 소진 후 → frag[0]부터 전부 소실

    item 64에서 소진되는 이유:
        item 1장 = 3회 전송 (probe1 + probe2 + aligned)
        63장 완료 = 189회 전송
        항목 간격 = probe 1s + (필요시 +2s) + do_swap_read ≈ 1.5~3s
        → 연속 항목들이 동일 5s 창 내에 쌓임
        → 5s 창 리셋 전에 burst 10 모두 소진

[4] 적용된 수정사항

    수정 1: _parse_sub_page1_gpa() 함수 추가
        위치: mura_dict_build.py:180–198
        기존: re.findall(r"sub-page\[\d+\]\s+GPA=0x...", dmesg) 사용
              → printk_ratelimited() 라인 → 드랍되면 GPA 못 구함
        변경: frag[0] 라인의 compound_GPA + off 값으로 직접 계산
              → printk_ratelimited()에 의존하지 않음
              → frag[0] 라인 1개만 있으면 GPA 복원 가능

    수정 2: reload_icmp_module() 함수 추가
        위치: mura_dict_build.py:304–315
        동작:
            lsmod에서 icmp 관련 모듈 이름 탐색
            modinfo로 .ko 경로 획득
            rmmod → insmod (timeout=20)
        효과: DEFINE_RATELIMIT_STATE static 변수 리셋
              → 5s 창당 burst=10 카운터 초기화
        호출 시점:
            build() 진입 시 1회
            DRAIN_EVERY(=16) 항목마다 drain_rxbuf() 직후 1회

    수정 3: time.sleep(6) — do_swap_read 직후
        위치: mura_dict_build.py:383
        이유: printk_ratelimited 5s 창이 만료되어야
              다음 항목의 첫 전송이 새 burst 카운터에서 시작
        6s = 5s 창 + 1s 여유
        효과: 항목 N의 마지막 전송과 항목 N+1의 첫 probe 사이
              반드시 5s 이상 경과 보장

    수정 4: SSH 초기화에 printk_ratelimit=0 추가
        위치: mura_dict_build.py:495
        대상: 전역 printk_ratelimit() 함수의 드랍 메시지 방지
        한계: printk_ratelimited() 매크로에는 효과 없음
              (보조 수단; 근본 수정은 수정 2+3)

    수정 5: _probe_once() 내 retry 루프 추가
        위치: mura_dict_build.py:244–256
        기존: sleep(0.5s) 후 1회만 dmesg 확인
        변경: 1s + 최대 3×2s = 총 최대 7s 대기, 파싱 성공 시 early exit
        효과: 느린 게스트 환경에서 dmesg 출력 지연 허용

    수정 6: build() 재실행 시 항상 새로 빌드
        기존: DICT_CACHE 로드 후 기존 항목 있으면 skip
        변경: cache = {"fixed_gpa": None, "refs": {}} 로 항상 초기화
              skip 로직 완전 제거

[5] ensure_mtu_9000() 추가 배경

    MTU < 8193이면 8193바이트 ICMP payload가 IP 단에서 분할됨
    IP 단편화 후 skb reassemble → skb_shinfo->frags 대신 frag_list 사용
    → 게스트 large_icmp_monitor가 frag[0] 를 못 찾음 → GPA 획득 실패

    수정: 빌드 진입 전 host TAP + guest iface MTU 9000 설정
          (ip link set <dev> mtu 9000)
          현재 이미 9000이면 skip

[6] 수정 후 동작 흐름

    build() 진입
    → ensure_mtu_9000()
    → SSH init (watchdog off, printk_ratelimit=0)
    → reload_icmp_module()            ← burst 카운터 초기화
    → FIXED_GPA 획득 (acquire_gpa None)
    → for i in 0..63:
          if i > 0 and i % 16 == 0:
              drain_rxbuf()
              reload_icmp_module()    ← 16항목마다 재리셋
          acquire_gpa(u8_val)
              probe1 → sleep 1s~7s 대기 → frag_p1_a
              probe2 → 동일               → frag_p1_b
              aligned send → 1s+retry → sub_page1_gpa (frag[0] 계산)
          do_swap_read(fixed_gpa, gpa_refX, out_path)
          sleep(6)                    ← 5s 창 만료 대기
          cache 저장
