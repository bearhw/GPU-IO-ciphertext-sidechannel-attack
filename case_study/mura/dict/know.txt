mura_dict_build.py Debugging Log — Confirmed Facts
Source: Direct observation of mura_dict_build.py --build execution results

[1] Build Pipeline Overview

    Objective: Generate ref_XXX.out files for each of the 64 REF_U8 values (SEV-SNP XOR slice dict)
    Tool: mura_dict_build.py (this directory)

    1 build run = Acquire FIXED_GPA (zero payload) + acquire 64 ref GPAs + swap_read

    GPA Acquisition Procedure (acquire_gpa):
    1. probe1: send zero ICMP -> parse frag[0] off=N from dmesg -> calculate frag_p1_a
    2. probe2: repeat identical probe                         -> calculate frag_p1_b
    3. delta = (frag_p1_a - frag_p1_b) % 4096
       expected_frag = (frag_p1_b - delta) % 4096
    4. aligned send: prefix=expected_frag bytes zero + ref payload
       -> sub-page[1] byte 0 = first byte of REF_CHUNK_X

    frag_p1 Calculation Formula:
        frag_off = off field value of frag[0]
        frag_p1  = 4096 - (frag_off % 4096) - 8   (8 = ICMP echo header)

    sub-page[1] GPA Calculation Formula:
        compound_gpa = compound_GPA field in frag[0] line
        frag_off     = off field in the same line
        start_page   = frag_off // 4096
        sub_page1_gpa = compound_gpa + (start_page + 1) * 4096

    PAYLOAD_SIZE = 8193 (Fixed):
        -> Same size used for both probe and aligned sends
        -> sub-page[1] always completely covered by payload (stable GPA)

[2] Issues Encountered — Progressions

    Symptom 1: frag_p1 parse failed (initial, probe sleep too short)
        Cause: Sleep 0.5s before reading dmesg — no dmesg output yet
        Resolution: 1s + max 3x2s retry (total max 7s wait)

    Symptom 2: Re-running --build skipped existing items (resumed from item 45)
        Cause: Code had DICT_CACHE load + skip logic
        Resolution: Completely removed cache load and skip logic from build()
                    -> --build always builds cleanly from scratch

    Symptom 3: ** 14 printk messages dropped ** (printed in dmesg)
        Cause: Default /proc/sys/kernel/printk_ratelimit is positive
               -> Global printk_ratelimit() function drops messages
        Resolution: Set printk_ratelimit=0 during SSH initialization
                    echo 0 | sudo tee /proc/sys/kernel/printk_ratelimit

    Symptom 4: [!] No GPA (item 63/64)
        Cause: 'sub-page[N] GPA=...' line missing in dmesg
               -> That line uses printk_ratelimited() macro
               -> Dropped regardless of sysctl printk_ratelimit=0
        Resolution: Calculate sub-page GPA directly from frag[0] line
                    (wrote new _parse_sub_page1_gpa function)

    Symptom 5: frag_p1 parse failed (item 64/64) <- Final failure mode
        Only 3 lines in dmesg:
            guest_large_icmp_monitor: handler fired!
            icmp type=0 ...
            payload_len=... nonlinear=1
        'frag[0]' line itself missing (all lines from 4th line onwards lost)

[3] Root Cause — printk_ratelimit vs printk_ratelimited

    Category        printk_ratelimit()           printk_ratelimited() Macro
    ──────────────────────────────────────────────────────────────────────
    Control Mode    Global single counter        DEFINE_RATELIMIT_STATE per call site
    sysctl Control  /proc/sys/kernel/            None (cannot reset via sysctl)
                    printk_ratelimit=0
                    can disable it
    Burst Limit     sysctl printk_burst          DEFAULT_RATELIMIT_BURST = 10
    Window Size     sysctl printk_ratelimit      DEFAULT_RATELIMIT_INTERVAL = 5s
    Reset Method    Change sysctl value          rmmod + insmod target module
    Drop Notice     "** N printk messages        None (silently dropped)
                     dropped **" printed

    Guest LARGE_ICMP Kernel Module:
        handler fired!    -> printk()              (unlimited)
        icmp type=...     -> printk()              (unlimited)
        payload_len=...   -> printk()              (unlimited)
        frag[0] ...       -> printk_ratelimited()  <- limited from line 4 onwards
        sub-page[N] GPA=  -> printk_ratelimited()

    After consuming burst=10 in 5s window -> everything from frag[0] is dropped

    Why exhaustion occurs at item 64:
        1 item = 3 transmissions (probe1 + probe2 + aligned)
        63 items completed = 189 transmissions
        Item interval = probe 1s + (retry if needed +2s) + do_swap_read ≈ 1.5~3s
        -> Consecutive items stack within the same 5s window
        -> All burst 10 consumed before 5s window resets

[4] Implemented Fixes

    Fix 1: Add _parse_sub_page1_gpa() function
        Location: mura_dict_build.py:180–198
        Original: Used re.findall(r"sub-page\[\d+\]\s+GPA=0x...", dmesg)
                  -> printk_ratelimited() line -> GPA unavailable if dropped
        Change: Directly calculate from compound_GPA + off in frag[0] line
                -> Independent of printk_ratelimited()
                -> Requires only 1 frag[0] line to recover GPA

    Fix 2: Add reload_icmp_module() function
        Location: mura_dict_build.py:304–315
        Behavior:
            Find ICMP module name in lsmod
            Obtain .ko path via modinfo
            rmmod -> insmod (timeout=20)
        Effect: Resets DEFINE_RATELIMIT_STATE static variable
                -> Re-initializes burst=10 counter per 5s window
        Invocation:
            Once upon entering build()
            Once after drain_rxbuf() every DRAIN_EVERY(=16) items

    Fix 3: time.sleep(6) — immediately following do_swap_read
        Location: mura_dict_build.py:383
        Rationale: Must expire printk_ratelimited 5s window
                   so the first transmission of next item starts with fresh burst counter
        6s = 5s window + 1s buffer
        Effect: Guarantees at least 5s elapsed between last transmission of item N and first probe of item N+1

    Fix 4: Add printk_ratelimit=0 to SSH initialization
        Location: mura_dict_build.py:495
        Target: Prevent drop messages from global printk_ratelimit() function
        Limitation: Ineffective on printk_ratelimited() macro
                    (supplementary; root fixes are Fix 2+3)

    Fix 5: Add retry loop inside _probe_once()
        Location: mura_dict_build.py:244–256
        Original: Checked dmesg once after sleep(0.5s)
        Change: 1s + max 3x2s = total max 7s wait, early exit upon successful parse
        Effect: Accommodates dmesg output delays in slower guest environments

    Fix 6: Always build fresh when re-running build()
        Original: Loaded DICT_CACHE and skipped existing items
        Change: Always initialize cache = {"fixed_gpa": None, "refs": {}}
                Completely removed skip logic

[5] Background for ensure_mtu_9000()

    If MTU < 8193, 8193-byte ICMP payload gets fragmented at IP layer
    After IP reassembly -> skb uses frag_list instead of skb_shinfo->frags
    -> Guest large_icmp_monitor cannot find frag[0] -> GPA acquisition fails

    Fix: Set host TAP + guest iface MTU to 9000 before build
         (ip link set <dev> mtu 9000)
         Skip if already 9000

[6] Operational Flow After Fixes

    Enter build()
    -> ensure_mtu_9000()
    -> SSH init (watchdog off, printk_ratelimit=0)
    -> reload_icmp_module()            <- Reset burst counter
    -> Acquire FIXED_GPA (acquire_gpa None)
    -> for i in 0..63:
          if i > 0 and i % 16 == 0:
              drain_rxbuf()
              reload_icmp_module()    <- Re-reset every 16 items
          acquire_gpa(u8_val)
              probe1 -> wait 1s~7s -> frag_p1_a
              probe2 -> repeat     -> frag_p1_b
              aligned send -> 1s+retry -> sub_page1_gpa (computed from frag[0])
          do_swap_read(fixed_gpa, gpa_refX, out_path)
          sleep(6)                    <- Wait for 5s window expiration
          save cache
